# ICNO 마켓 개발 계획서

작성: 서승린
결정: 대상 = **아이콘 + 프리셋 둘 다** / 백엔드 = **Supabase(신규 세팅)** / 범위 = **인증부터 전체(업로드+탐색+다운로드)**
원칙: 보안이 가장 중요한 기능. 체크리스트 D/E/F 항목을 여기서 실제로 구현한다.

---

## 1. 아키텍처

```
React 프론트(브라우저)
   │  ├─ Supabase Auth      (회원가입/로그인)
   │  ├─ Supabase DB        (메타데이터 조회, RLS 적용)
   │  └─ Edge Function      (★ 업로드는 반드시 여기 통과 = 보안 게이트웨이)
   │                            → 이미지 검증/재인코딩/해시 → Storage + DB 기록
   │
로컬 엔진(FastAPI)  ← 다운로드한 마켓 자산을 실제 바탕화면에 적용 (기존 그대로)
```

**핵심 보안 설계**
- 업로드는 **클라이언트가 Storage에 직접 쓰지 않고**, 반드시 **Edge Function(서버)**을 거친다. 서버에서 검증 후 저장. (클라이언트 신뢰 금지)
- 조회/다운로드는 DB + Storage 공개 읽기, 단 **RLS**로 권한 통제.
- 공유 자산에는 **실행 매핑(target_path) 미포함**, **절대경로 없음**(id/논리식별자만).

---

## 2. 데이터 모델 (초안)

**테이블**
- `profiles` — 사용자 프로필 (id=auth.uid, 닉네임, 아바타). 회원가입 시 생성.
- `market_icons` — 개별 아이콘. (id, owner_id, 이름, 태그[], 카테고리, storage_path, sha256, width/height, 다운로드수, 좋아요수, is_public, created_at)
- `market_presets` — 프리셋. (id, owner_id, 이름, 설명, 태그[], wallpaper_path, canvas, icons(jsonb: asset 참조+배치, **실행매핑 제외**), sha256, 다운로드수, 좋아요수, is_public, created_at)
- `likes` — (user_id, target_type, target_id) 유니크
- `downloads` — (user_id, target_type, target_id, created_at)  ← 통계/중복방지
- `reports` — 신고 (reporter_id, target_type, target_id, reason, status)  ← 콘텐츠 검수용

**Storage 버킷**
- `market-icons` — 아이콘 이미지 (PNG 재인코딩본)
- `market-preset-images` — 프리셋 배경/아이콘 이미지

## 3. 보안 (체크리스트 실제 적용)

**RLS 정책 (필수)**
- 조회: `is_public = true` 인 행은 누구나 SELECT. 본인 소유는 항상.
- 삽입: `auth.uid() = owner_id` (로그인 + 본인 명의만)
- 수정/삭제: `auth.uid() = owner_id` (소유자만 → IDOR 방지)
- likes/downloads/reports: 로그인 사용자, 본인 행만.

**업로드 파이프라인 (Edge Function 안)**
1. 로그인(JWT) 검증 → owner_id = 요청자
2. **매니페스트 스키마 검증**(미선언 필드 거부, 대량할당 방지)
3. **이미지 검증**: 실제 이미지 확인 + **PNG 재인코딩 + EXIF 제거** + 용량/차원/개수 상한
4. **실행 매핑/절대경로 제외** 강제
5. **sha256** 계산·기록 (중복 제거, 다운로드 시 무결성 검증)
6. 통과분만 Storage + DB 기록

**저장형 XSS 대비 (프론트)**
- 이름/설명/태그/닉네임 등 사용자 텍스트는 **출력 시 자동 이스케이프**, `dangerouslySetInnerHTML` 금지.
- 입력 정규화 + 길이 제한.

**검수/운영**
- 신고 버튼 + `reports` 큐. 레이트 리밋. (마켓 오픈 전 최소 신고 기능은 필요)

> 참고: Edge Function(Deno)의 이미지 재인코딩은 라이브러리 제약이 있어, PNG/JPEG는 재인코딩, **GIF는 구조 검증만/또는 정적만 허용**으로 Phase 3에서 확정한다.

## 4. 단계별 로드맵

| Phase | 내용 | 담당 |
|---|---|---|
| **0** | Supabase 프로젝트 생성 + 프론트 연결(URL/anon key) | 사용자(내가 안내) |
| **1** | 인증 — Supabase Auth + `profiles` + 로그인/회원가입 UI (기존 mock 로그인 대체) | 나(설정/SQL) + Lovable(UI) |
| **2** | 데이터 모델 + RLS — 테이블/버킷 생성 + RLS 정책 | 나(SQL) + 사용자(대시보드 실행) |
| **3** | ★ 보안 업로드 파이프라인 — Edge Function(검증/재인코딩/해시) | 나(코드) + 사용자(배포) |
| **4** | 업로드 UI — 아이콘/프리셋을 마켓에 올리는 화면 | Lovable |
| **5** | 탐색/다운로드 — 목록/검색/상세(실데이터) + 다운로드→로컬 적용 | Lovable + 나(로컬 연동) |

각 Phase는 독립 검증 가능하게 진행. 보안이 핵심인 Phase 3은 특히 신중히.

---

## 5. 역할 분담

- **사용자**: Supabase 대시보드 작업(프로젝트/키/SQL 실행/버킷/Edge Function 배포). 내가 정확한 단계·SQL·코드를 제공.
- **나(로컬/설계)**: 스키마 SQL, RLS 정책, Edge Function 코드, 보안 파이프라인, 로컬 엔진 다운로드 연동, Lovable 요청문.
- **Lovable**: 로그인/업로드/탐색 UI (프론트).
