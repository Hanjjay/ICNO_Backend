## 0. 먼저 멘토에게 밝힐 것 — "내 목표"

상담의 방향이 완전히 달라지므로, 시작할 때 본인 목표를 먼저 말하는 게 좋습니다. 아래 중 무엇에 가까운지 스스로 정해서 전달하세요.

- 포트폴리오 / 취업용 프로젝트
- 사이드 프로젝트 → 실제 사용자에게 배포
- 창업(수익화·투자·법인) 목표
- 대회·공모전 입상 목표
- 연구/특허 목표

(여러 개일 수 있지만 "1순위"를 정해두면 멘토가 조언을 집중해 줍니다.)

## 1. 프로젝트 한 줄 소개 (멘토에게 먼저 설명)

> "Windows 바탕화면의 배경·아이콘 이미지·배치·크기를 **프리셋 단위**로 만들고, 사용자가 프리셋을 **업로드·공유·다운로드·적용**할 수 있는 데스크톱 커스터마이징 앱입니다."

### 현재 아키텍처
```
Lovable(React/Vite) 웹 프론트
        ↓ (로컬 API)
사용자 PC의 로컬 FastAPI
        ↓
PySide6 오버레이 엔진 → 실제 Windows 바탕화면 변경
```
- 핵심 설계 원칙: **클라우드는 바탕화면을 직접 바꾸지 않는다. 실제 변경은 사용자 PC의 로컬 엔진이 수행한다.** (로컬/클라우드 API 분리)

### 지금 되는 것 (로컬 검증 완료)
- 아이콘 업로드·보관함(중복 방지, 실제 파일 저장)
- 프리셋 저장·삭제·이름변경·썸네일
- **프리셋 전체 적용**: 배경화면 + 아이콘 배치/크기 + 기본아이콘 숨김 + 오버레이 (원자적 적용, 실패 시 롤백)
- 해상도·DPI 배율 자동 보정(미리보기=실제 일치)
- 배경화면 원복(끄기/종료), 트레이 메뉴
- 아이콘 클릭 시 프로그램 실행(매핑)

### 아직 안 된 것
- 클라우드(회원·마켓·업로드/다운로드·좋아요·북마크)
- 배포용 설치 패키지, 코드 서명
- 다른 PC로 프리셋 이식(절대경로 문제)
- 보안 정책 전반

## 2. 상담 주제별 질문

### A. 아키텍처 & 클라우드 로드맵
- 로컬 엔진 ↔ 클라우드를 어떻게 나누고 동기화하는 게 좋을까요? (인증, 프리셋 저장 위치)
- 클라우드 스택 추천: AWS? 서버리스(Lambda/S3)? Supabase(이미 프론트에 붙어있음) 확장?
- **프리셋 이식성**: 프리셋에 `C:\Users\...` 절대경로를 담으면 안 되는데, 다른 PC에서도 아이콘/프로그램을 재연결하려면 어떤 식별자 체계(logical_target, 실행파일명 등)가 현실적일까요?
- **로컬 엔진 배포·자동업데이트**: Python+PySide6 엔진을 어떻게 설치·갱신시키는 게 좋을까요?
- 지금의 "웹 프론트 + 로컬 엔진" 구조 vs Electron 단일 앱 — 어느 쪽이 유지보수·배포에 유리할까요?

### B. 보안 & 개인정보 (이 앱에서 특히 중요)
이 앱은 **강한 권한**을 씁니다: 배경화면 변경, 기본아이콘 숨김, **임의 프로그램 실행(os.startfile)**, 창 오버레이, 로컬 HTTP 서버(FastAPI 8000, 오버레이 IPC 19876) 운영.
- **다운로드한 프리셋이 악성 실행경로(target_path)를 담고 있으면** 클릭 시 악성 프로그램이 실행될 수 있습니다. 마켓에서 받은 프리셋을 어떻게 안전하게 검증/제한할까요? (예: 공유 프리셋엔 실행매핑 제외, 사용자가 직접 재지정)
- 로컬 서버를 127.0.0.1로만 바인딩했는데, 다른 앱/웹이 이 로컬 API를 호출하는 것(CSRF 유사)은 어떻게 막을까요? (토큰, Origin 검증)
- 사용자 데이터 중 **클라우드로 올라가는 것/안 올라가는 것**의 경계를 어떻게 잡을까요? 개인정보 처리방침이 필요할까요?
- 오버레이·프로세스 조작 때문에 **백신(Windows Defender)이 오탐**할 가능성 — 어떻게 대비하나요?

### C. 배포 & 출시
- 로컬 엔진 패키징: PyInstaller / Nuitka 중 무엇이 나을까요? 용량·구동속도·오탐 측면에서.
- **코드 서명 인증서**가 없으면 Windows SmartScreen 경고가 뜨는데, 개인/1인 개발자가 서명하려면 비용·절차가 어떻게 되나요? 꼭 필요한가요?
- 배포 채널: 자체 웹 다운로드 vs Microsoft Store — 각 장단점?
- macOS/Linux 확장 계획은 현실적으로 언제·어떻게?
- 초기 사용자 확보/피드백 방법?

### D. 비즈니스 모델 & 수익화
- 수익 모델 아이디어(크리에이터 마켓 수수료 / 프리미엄 프리셋 / 구독)가 이 앱에 맞을까요?
- 타깃 사용자층과 시장 규모를 어떻게 검증하면 좋을까요?
- MVP를 어디까지 잡고 언제 출시하는 게 좋을까요?

### E. 지식재산권 (특허/저작권/상표)
- 이 방식(오버레이 기반 아이콘 교체 + 프리셋 공유 시스템)이 **특허(또는 실용신안)로 보호 가능한 발명**인지, 아니면 이미 유사 선행기술이 있는지 궁금합니다.
- **중요: 공개 배포/공모전 출품이 특허 신규성을 훼손할 수 있다고 들었습니다.** 특허를 고려한다면 공개 전에 무엇을 먼저 해야 하나요? (선출원, 임시명세서 등)
- 이름 "ICNO/INCO"의 상표 등록은 필요/가능한가요?
- 코드·디자인 저작권 측면에서 오픈소스 라이브러리(PySide6 등) 사용 시 주의점은?

> ※ 특허·법률은 전문 영역이라, 멘토 상담 후 필요하면 변리사/특허사무소 무료상담(공공기관 지원)도 병행하는 게 안전합니다.

### F. 대회 / 공모전 / 창업지원
- 제 상황(개인/학생 개발자, 실동작 프로토타입 보유)에 맞는 **창업지원 사업이나 SW 공모전**이 있을까요? (예: 예비창업패키지, K-Startup, 대학 창업지원단, SW/정보보호 공모전 등)
- 심사에서 이 앱의 강점(실제 동작하는 데스크톱 커스터마이징 + 공유 생태계)을 어떻게 어필하면 좋을까요?
- 지원·출품에 **법인 설립, 팀 구성, 사업계획서**가 필수인가요? 혼자여도 가능한가요?
- 특허 출원과 공모전 출품의 **순서**(신규성 이슈)를 어떻게 잡아야 하나요?
