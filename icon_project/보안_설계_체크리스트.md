# ICNO 보안 설계 체크리스트

작성: 서승린
목적: 멘토 피드백 + 자체 점검 항목을 한 곳에 모아, 완료/진행/예정으로 관리한다.
범위 구분: **[로컬]** = 지금 프로토타입에서 처리 / **[클라우드]** = 마켓·서버 붙일 때 처리

---

## A. 완료 (로컬 프로토타입)

- [x] **로컬 API Origin 검증 (CSRF 방어)** — 상태변경 요청 + 민감 GET(pick-file)에 Origin 허용목록 검증, 미허용 시 403. (`origin_guard` 미들웨어)
- [x] **릴리스 시 /docs·openapi 비활성화** — `ICNO_DEV=0`으로 실행 시 API 명세 노출 차단. 배포는 `--reload` 없이.
- [x] **파일명 UUID 생성** — 업로드 저장 파일명에 원본 파일명 미사용(순수 UUID) → 경로 탈출·이름 위조 원천 차단.
- [x] **경로 심층 방어 (realpath + basePath)** — `_is_within()`으로 저장/사용 경로가 반드시 지정 폴더 안인지 검증. 적용처: 아이콘 업로드, 배경 업로드, `wallpaper/apply`, `apply-local`의 image_path·wallpaper_path, 보관함 삭제.
- [x] **이미지 무결성 + 용량 검증** — PIL `verify()`로 실제 이미지 확인(확장자 위조·손상 파일 차단), 용량 상한(아이콘 15MB / 배경 40MB), 디컴프레션 봄 방지(`MAX_IMAGE_PIXELS`), 정적 이미지 PNG 재인코딩.
- [x] **대량 할당(mass assignment) 방지** — `patch_preset`의 중첩 값(settings/canvas/icons)을 타입 모델로 재검증해 미선언 필드 주입 차단. `create_preset`은 서버가 id를 항상 발급(클라이언트 id로 덮어쓰기 방지).

---

## B. 진행 예정 (로컬에서 곧 처리)

- [ ] **/api/calculate 의 `eval()` 제거** — 안 쓰는 계산기 잔재. 원격 코드 실행 위험이라 삭제.
- [ ] **⑤ 아이콘↔프로그램 실행 매핑 화이트리스트** — `target_path` 실행을 임의 경로가 아니라 **내 PC에 이미 설치된 앱 목록 범위 안에서만** 검증·실행. (다운로드 프리셋의 악성 실행 경로 차단)
- [ ] **⑥ icons_config.json 변조 방지** — 실행 대상을 담은 설정 파일을 `%LOCALAPPDATA%` 등 사용자 권한 영역으로 이전해 변조 난이도를 높임.
- [ ] **IPC 서버(오버레이 19876) 최소 보호** — 무인증 로컬 포트. 최소한 로컬 전용 바인딩 확인 + 필요 시 토큰.

---

## C. 배포 단계 (릴리스 전)

- [ ] **⑦ 코드 서명** — 서명 없으면 백신·SmartScreen 오탐. 설치 관리자·실행 파일 서명 검토.
- [ ] **릴리스 실행 설정 고정** — `ICNO_DEV=0`, `ICNO_ALLOWED_ORIGINS=<실제 프론트 도메인>`, `--reload` 미사용.

---

## D. 마켓 업로드 무결성 [클라우드]

> 마켓은 아직 미구현. 클라우드 API 업로드 엔드포인트에서 **서버측에서** 아래를 한 번에 검사한다. (브라우저 사전검증은 UX용일 뿐, 서버는 클라이언트를 신뢰하지 않고 재검증)

- [ ] **매니페스트 스키마 검증** — 프리셋 구조가 정해진 스키마와 정확히 일치(Pydantic). 미선언·이상 필드 거부(대량 할당 방지).
- [ ] **이미지 재검증 + 재인코딩** — 모든 이미지 `verify()` 후 서버에서 PNG로 재저장. 용량·차원 상한.
- [ ] **이미지 메타데이터(EXIF) 제거** — 개인정보 + 페이로드 은닉 방지.
- [ ] **확장자 ↔ 실제 형식 일치 확인** — 매직바이트로 실제 타입 검사(위조 차단).
- [ ] **실행 매핑·절대경로 제외** — `target_path` 미포함, 절대경로 대신 논리 식별자만 저장.
- [ ] **개수/총용량 상한** — 프리셋당 아이콘 수·전체 용량 제한(남용·DoS 방지).
- [ ] **sha256 해시 저장** — 자산별 해시 기록 → 다운로드 시 클라이언트 무결성 검증 + 중복 제거.

---

## E. 저장형 인젝션(Stored XSS) & 콘텐츠 검수 [클라우드]

> 마켓은 사용자 생성 콘텐츠(프리셋 이름·설명·태그·제작자명·댓글)를 저장했다가 **다른 사용자에게 렌더링**한다. 여기서 저장형 XSS/인젝션이 발생한다.

**정확히 알아둘 것**
- **JSON 파싱 자체는 코드 실행이 아니다.** `JSON.parse`는 안전. 위험은 파싱된 값을 **화면에 렌더링하거나(XSS) 쿼리·명령·이메일에 넣을 때(인젝션)** 발생 → 벡터는 "디코딩"이 아니라 **"출력·사용" 시점**.
- **이중 URL 인코딩 우회**: 한 번만 디코드+검사하면 이중 인코딩 페이로드가 빠져나감 → 검증 전에 **완전 정규화(canonicalize)** 후 검사 + **출력 시점 이스케이프**로 이중 방어.

**방어 항목**
- [ ] 모든 사용자 입력 필드를 불신 처리. 출력 시 **자동 이스케이프(React 기본)** 활용, **`dangerouslySetInnerHTML` 금지**(불가피하면 DOMPurify로 정화).
- [ ] 프리셋 JSON은 **데이터만** — HTML/SVG/스크립트 필드 불허, 엄격한 스키마(미선언 필드 거부, 로컬엔 이미 적용). 이미지는 PNG 재인코딩(적용됨).
- [ ] 입력 **정규화 + 길이 제한 + 문자 제한(가능한 필드)** + 제어문자 제거.
- [ ] **콘텐츠 검수(모더레이션)**: 자동(스키마·이미지 재인코딩·용량/개수 상한·금칙어·해시 기반 악성 탐지) + **신고 버튼 + 검수 큐**. 신규 업로드는 필요 시 격리/플래그.
- [ ] **알림/이메일 인젝션 방지**: 사용자 콘텐츠를 이메일/알림에 넣을 때 반드시 이스케이프. 이메일은 평문 또는 이스케이프 템플릿, 알림은 텍스트로 렌더(HTML 렌더 금지).
- [ ] **레이트 리밋** — 스팸·대량 악성 업로드 방지.

**Supabase 관련 (정확히)**
- [ ] **SQL 인젝션**: 클라이언트의 파라미터화 쿼리를 쓰면 대부분 안전. 단 **원시 SQL 조합·`.rpc` 직접 작성 시 재발생** 주의.
- [ ] **RLS(Row Level Security) 필수** — 안 켜면 anon 키로 전체 데이터 노출(Supabase 최대 실수). 소유자 스코프 정책 작성.
- [ ] 스토리지 버킷 공개/인증 정책 정확히 설정.
- [ ] **저장형 XSS는 Supabase가 막지 않음** — 페이로드를 그대로 저장할 뿐, XSS는 렌더 시점(프론트)에서 터짐. SQLi는 상당수 커버하지만 **XSS·콘텐츠 검수는 애플리케이션 책임**.

---

## F. 아키텍처 방향 (근본 대응)

- [ ] **경로를 클라이언트에서 받지 않는 구조로 전환 [클라우드]** — Supabase 등 서버 도입 시, API가 경로(path) 대신 **id만** 받고 서버가 내부 테이블에서 id→경로로 매핑. 경로 조작 공격면 자체를 제거.
  - 지금도 `apply-local`은 이미 asset_id 기반(절반 적용). 남은 경로 입력(`wallpaper/apply`의 wallpaper_path)도 id 방식으로 승격.
- [ ] **사용자 스코프 권한 검증 [클라우드]** — 프리셋·자산을 소유자 기준으로 스코프. 남의 리소스 id로 수정·삭제(IDOR) 방지.

---

## 참고 — 설계 원칙 (변하지 않는 것)

- 클라우드는 바탕화면을 직접 바꾸지 않는다. 실제 Windows 변경은 로컬 엔진만 수행한다.
- 공유(마켓) 프리셋에는 실행 매핑(target_path)을 담지 않는다. 실행 연결은 각 사용자가 자기 PC에서 직접 한다.
- 서버는 클라이언트를 신뢰하지 않는다. 모든 검증은 서버측에서 다시 한다.
